# SmartCorral（灵栅）—— 每屏桌面宿主架构 PRD

> 本文档供独立实现参考。**除了「每屏桌面宿主」架构和下方列出的已知大坑外，技术栈、框架、实现方式均不限制，可自由选择。**

---

## 1. 产品定位

SmartCorral（灵栅）是一款 Windows 桌面整理工具。核心体验：

- 桌面上显示若干半透明的**分类框（Frame / Fence）**，类似 Fences/Rainmeter 桌面小组件。
- 用户可**手动拖入**桌面文件到框里，也可由 **AI 自动分类**。
- 文件被收入框后，从 Windows 原生桌面**消失**（物理移动到托管目录），但在框里仍可正常**左键启动、右键系统菜单**。
- **退出 / 崩溃**后，所有被托管的文件**安全还原**回桌面原位。
- 支持多显示器、不同 DPI 缩放率。
- 按下 Win+D（显示桌面）时，框**保持显示**——它们是桌面的一部分。

## 2. 核心架构指令：每屏桌面宿主

### 2.1 目标

每个物理显示器创建一个**独立的透明宿主窗口**，挂入 Windows 桌面层（Progman 或 WorkerW）。框（Fence）是宿主窗口内的**控件/元素**（不是独立窗口）。

```
显示器 1 (150% DPI)              显示器 2 (100% DPI)
┌─────────────────────┐          ┌──────────────────┐
│ HostWindow-1        │          │ HostWindow-2     │
│ (DPI=150%, 挂Progman)│          │ (DPI=100%,挂Progman)│
│                     │          │                  │
│  ┌────────┐         │          │  ┌─────────┐     │
│  │ Frame A│         │          │  │ Frame C │     │
│  └────────┘         │          │  └─────────┘     │
│  ┌────────┐         │          │                  │
│  │ Frame B│         │          │                  │
│  └────────┘         │          │                  │
│  (空白处点击穿透)    │          │  (空白处点击穿透) │
└─────────────────────┘          └──────────────────┘
         ↑                                ↑
   普通应用窗口在宿主之上             普通应用窗口在宿主之上
```

### 2.2 为什么每屏独立

- **多 DPI 完美**：每个宿主窗口有自己的 DPI（该显示器 的缩放率），内容在该屏清晰。
- **不是跨屏大窗口**：避免一个窗口跨多屏导致 DPI 统一、副屏模糊。

### 2.3 每屏宿主的核心要求

1. **每个显示器一个宿主窗口**：`Size = 该显示器的工作区`，`DPI = 该显示器的 DPI`。
2. **挂入桌面层**：`SetParent(hostHwnd, Progman 或 WorkerW)`。这样宿主成为桌面的一部分，Win+D 不会隐藏它。
3. **透明 + 点击穿透空白**：宿主窗口背景透明。空白区域点击穿透到桌面（用户能点壁纸/图标）。框区域正常交互。
4. **框是宿主内的控件**（不是独立 OS 窗口）。框的拖拽/缩放在宿主坐标系内进行。
5. **跨屏拖拽**：框从一个宿主拖到另一个时，从源宿主的控件树迁移到目标宿主的控件树。坐标按物理像素连续转换。
6. **显示器热插拔**：显示器连接/断开时创建/销毁对应宿主，框迁移到主屏宿主。
7. **Win+D 原生免疫**：因为宿主挂在桌面层（Progman 子窗口），"显示桌面"时宿主天然可见——不需要监听 Win+D、不需要 Topmost、不需要重断言。

### 2.4 挂载目标选择（必须实现降级）

```
首选：SetParent(host, Progman)        ← GetShellWindow()，100% 可靠
备选：SetParent(host, WorkerW)       ← 需要查找（多屏可能失败）
降级：不挂载，以普通窗口运行           ← 宁可降级，不猜不强制
```

**重要**：多显示器环境下可能有 N 个 WorkerW 窗口（不一定在 Progman 之后），经典查找算法（SHELLDLL_DefView → next WorkerW）可能失败。**WorkerW 挂不上去时，必须降级到 Progman 或普通窗口，绝不猜。**

## 3. 功能清单（必须实现）

### 3.1 桌面文件托管（Custody）

- 文件/文件夹/.lnk/.url 被收入框时，**物理移动**到托管目录（如 `%LOCALAPPDATA%\SmartCorral\custody\`）。
- 托管目录必须与桌面**同卷**（保证 `Move` 原子性）。
- 移动前先写**清单**（记录 originalPath + custodyPath），移动后标记完成。
- 框内显示文件的图标 + 名称，可**左键启动**、**右键系统菜单**（菜单作用在托管副本上）。
- 从框移除（拖出/删除框）时，文件**还原**回桌面原位。

### 3.2 AI 自动分类

- 启动时扫描桌面，调用 OpenAI 兼容 API（可配置 Base URL / API Key / Model）。
- LLM 返回每个文件的分类（≤5 个大类），创建分类框并归入。
- 分类是增量的：已归档的文件跳过。
- 没分出类的文件**留在桌面**（不强行归入）。

### 3.3 增量自动分类（FileSystemWatcher）

- 监听桌面目录，新文件出现后（去抖 ~4 秒等待写入完成）自动交给 AI 分类。
- **只处理新出现的文件**——已归档的/留桌面没分出类的（leftover）**不重复处理**。
- 下载临时文件（`.crdownload`/`.part`/`.tmp`/`~$`）跳过。
- 批量操作（退出还原、重新归类）期间暂停监听。
- 文件从框拖回桌面（释放）后，监听器应**临时忽略该路径**（~15 秒），避免秒抓回。

### 3.4 手动交互

- **拖入**：从桌面拖文件到框 → 移入托管 + 框内显示 + 桌面消失。
- **拖出**：从框拖文件到桌面/Explorer → 释放（还原回桌面 + 从框移除）。
- **框间拖**：从一个框拖到另一个框 → 重新归类（托管文件不动，只改框归属）。
- **框 chrome**：标题栏拖拽、双击卷起/展开、右键菜单（新建框/改名/锁定/卷起/删除）、缩放手柄。
- **磁吸**：拖拽/缩放时对齐屏幕边缘和其他框（蓝色对齐线提示）。
- **右键文件图标**：原生 Windows 系统菜单（Open/Delete/Properties…）。如果用户选了删除，文件进回收站，框内图标自动移除（不留死链）。

### 3.5 系统托盘

- 托盘图标 + 菜单：设置 / 整齐排列框 / AI 重新归类 / 还原所有文件 / 退出。
- 设置：AI 配置（Base URL / API Key / Model）、每行图标数、文件夹分行、总置顶开关、日志开关、增量归类开关。

### 3.6 安全网（必须健壮）

- **退出**：所有托管文件还原回桌面 + 清单清空。
- **崩溃**：下次启动先还原所有托管文件（崩溃自愈），再重新托管已归档的。
- **还原冲突**：原位已有同名文件 → 改名还原（`xxx (restored).ext`），绝不覆盖。
- **还原失败**（文件被占用/锁住）→ 保留在托管目录、清单保留、下次重试。退出时弹气泡提醒用户。
- **文件被占用**（运行中的 exe）→ 移动失败时不创建半成品（不加进框，文件留在桌面），日志记录。
- **死链接清扫**：启动时检测——托管副本已不存在但框里还有记录的（死链接），自动移除。
- **孤儿文件还原**：启动时检测——托管目录里有文件但没有任何框引用（孤儿），还原回桌面。
- **重复去重**：启动时检测——同一原路径有两个框引用（重复），保留首个。

### 3.7 多显示器 + DPI

- 每个显示器独立宿主窗口，各自 DPI。
- 框跨屏拖拽时不跳（物理像素连续跟踪）。
- 显示器热插拔时宿主窗口增减。

## 4. 已知大坑（必须处理）

> 以下问题在之前版本的 SmartCorral 中**全部踩过并修复**。新实现必须从设计阶段就考虑。

### 4.1 Win+D / "显示桌面"

**问题**：Win+D 会最小化/隐藏普通窗口，导致框消失。Win11 的"显示桌面"不真正最小化窗口（不设 WS_MINIMIZE），而是抬起桌面层覆盖非置顶窗口。

**本架构的解法**：每屏宿主挂入桌面层（Progman/WorkerW），是桌面的一部分，Win+D 原生不影响——**不需要 Topmost、不需要监听、不需要重断言**。这是本架构的核心优势。

**如果挂载失败（降级模式）**：回退到普通窗口 + 前台跟踪（Win+D 时桌面成为前台 → 临时置顶 → 切回窗口时取消）。降级模式会有轻微闪烁，但能用。

### 4.2 全屏透明覆盖窗口的陷阱

**问题**：如果实现磁吸对齐线等效果需要一个全屏透明 Topmost 窗口，该窗口**不能常驻显示**。一个全屏 + Topmost + 透明的窗口（即使背景透明）在 topmost 带里会触发分层窗口合成 bug，导致某个框在 Win+D 时消失。

**解法**：只在需要时（拖拽中）`Show()`，结束后 `Hide()`（隐藏窗口本身，不只是隐藏线条）。

### 4.3 WorkerW 查找在多屏下可能失败

**问题**：经典 WorkerW 查找算法（枚举顶层窗口 → 找 SHELLDLL_DefView 宿主 → 取其后一个 WorkerW）在多显示器 + 某些壁纸配置下可能返回 0（有多个 WorkerW 但不在预期位置）。

**实测数据**：某台 3 屏机器有 **16 个 WorkerW** 窗口，经典算法返回 0。

**解法**：
1. 先试 Progman（`GetShellWindow()`，稳定可靠）。
2. Progman 不行再试 WorkerW（枚举 + 逐个测试）。
3. 都不行 → 降级普通窗口。

### 4.4 跨 DPI 拖拽跳跃

**问题**：拖拽框跨过不同 DPI 的显示器边界时，框位置会"跳"一下。因为拖拽 delta 除以了当前 DPI，而 DPI 在跨屏瞬间变了。

**解法**：拖拽全程用**物理像素**跟踪，最后除以当前 DPI 得 DIP：
```
物理位置 = 起始物理位置 + (当前鼠标物理坐标 - 起始鼠标物理坐标)
DIP位置 = 物理位置 / 当前DPI
```
DPI 变了，物理位置不变，只是 DIP 数值变。无跳跃。

### 4.5 图标缓存与 .lnk wrapper

**问题**：如果为桌面文件创建 wrapper .lnk（快捷方式指向托管副本），启动时重新指向新托管路径后，图标缓存可能返回旧图标（指向已失效的旧路径，回退到带箭头的 .lnk 图标）。导致非快捷方式文件错误地显示快捷方式箭头。

**解法**：重新指向后**清空图标缓存**。

**替代方案**：不用 wrapper .lnk，框内只显示内存中的 stub（图标 + 文字），点击/菜单直接代理给托管真文件。这样完全没有 wrapper 管理。

### 4.6 公共桌面写权限

**问题**：`C:\Users\Public\Desktop` 下的快捷方式，普通用户可能只有读权限、没有写权限。托管的文件还原到公共桌面时会失败。

**解法**：还原时原位不可写 → 回退到当前用户的个人桌面（`%USERPROFILE%\Desktop`）。日志记录。

### 4.7 增量监听器的误触发

**问题**：退出还原把文件搬回桌面 → FileSystemWatcher 看到"新文件" → 立刻自动归类 → 文件又被移走。用户刚还原的文件被秒抓。

**解法**：还原操作（退出/还原所有文件/拖出释放）后，对涉及的路径**临时拉黑**（~15 秒），监听器跳过。

### 4.8 运行中的文件移不动

**问题**：运行中的 exe 或含运行中 exe 的文件夹被锁定，`File.Move` / `Directory.Move` 失败。

**解法**：移动失败时不创建半成品 item（文件留在桌面，不进框，日志记录）。退出还原时同样可能失败 → 保留在托管目录、清单保留、下次重试。退出时弹气泡提醒。

### 4.9 框窗口不应抢焦点

**解法**：设置 `WS_EX_NOACTIVATE`。点击框/图标不切换键盘焦点，用户正在打字的窗口不受影响。

## 5. 数据模型（参考，不强制）

```
AppData:
  Frames: list of Frame
    - Id, Title, X, Y, Width, Height, IsLocked, IsRolled
    - Items: list of FrameItem
      - DisplayName, IsFolder, SourcePath (原桌面路径), Target (当前指向), DisplayOrder

CustodyManifest:
  list of { OriginalPath, CustodyPath, Done }

AppSettings:
  AiBaseUrl, AiApiKey, AiModel, IconsPerRow, SeparateFolders, EnableIncrementalCategorize, EnableLogging
```

持久化为 JSON（便携、可人工恢复）即可。不需要数据库。

## 7. 验收标准

1. 框出现在桌面上（半透明，能看到壁纸）。
2. 拖桌面文件到框 → 文件从桌面消失、框内出现、左键能启动、右键有系统菜单。
3. Win+D → 框**保持显示**（不闪烁、不消失）。
4. 打开普通窗口 → 窗口盖住框（框不挡屏）。
5. 多显示器不同 DPI → 每个屏的框内容清晰；跨屏拖框不跳。
6. 托管 → 退出 → 桌面所有文件还原。托管 → 崩溃 → 重启 → 自动还原 + 重新托管。
7. 新文件落到桌面 → ~5 秒后自动归类进框。
8. 拖框内文件到桌面 → 文件还原回桌面、从框移除。拖到另一个框 → 重新归类。
9. 右键框内图标 → 原生系统菜单；选删除 → 文件进回收站、框内图标消失。
10. 托管期间不会有文件丢失（原子移动 + 冲突改名 + 死链接清扫 + 孤儿还原）。
